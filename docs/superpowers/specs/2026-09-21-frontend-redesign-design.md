# 前端 UI/UX 改版設計：住戶端與團主端

**日期：** 2026-09-21
**狀態：** 已與團主逐段確認，待實作計畫

## 背景與目標

功能與資訊持續增加，兩端畫面越堆越長、資訊層級混亂，住戶端與團主端也像兩套產品（住戶端深綠漸層、團主端藍色）。這次重新設計視覺、資訊架構與操作流程，解決團主與住戶實際卡住的地方：

- **團主**（平常用電腦；一團約 50 筆訂單，品項 1～20 個）：開新團填內容很慢、設定太多不好找；開團期間不好盯單。
- **住戶**（在 LINE 裡用手機，也有人用電腦）：找不到該點哪個團、下單流程不直覺、不知道自己訂了什麼、不知道何時到貨與怎麼改單。

視覺語言參考團主提供的 DESIGN.md（單一藍色操作色、白底與淺灰底、無漸層與卡片陰影、膠囊形主要按鈕），**取其風格，密度依任務調整**：團主端做成資訊密集的工作台，住戶端以商品圖片與公告為主。

## 範圍

**這次做（只改前端）：** 視覺、資訊架構、操作流程、前端路由、共用元件，以及只用既有資料就能完成的前端小功能。

**這次不動：** 資料庫 schema、RLS、RPC、view、Edge Functions、Storage 權限、LIFF 與 Supabase Auth 流程、gateway 的公開介面。

**待辦清單（耗時，之後另案）：**

1. 住戶跨團「我的訂單」總覽：列表卡片顯示「你已訂 N 個、$X」，並決定是否讓住戶看到自己的付款狀態。需要新增唯讀 RPC 與 migration。
2. 複製上一團：建立草稿＋複製 Storage 圖片到新團資料夾（不能沿用舊網址，舊團刪除會清掉圖片）＋存草稿。需驗證 Storage copy 權限。
3. 從公告自動帶出品項：解析「(A)牛奶」「A 牛奶 $45」等寫法，產生建議讓團主確認。
4. 品項批次貼上、從中間插入／刪除、拖曳排序。

## 已確認的決策

| 決策 | 結論 |
|---|---|
| DESIGN.md 套用程度 | 取風格（色彩、按鈕、無陰影漸層），密度依任務調整 |
| 團主端架構 | 每一團有自己的工作區，左側欄切換分區（概況／訂單／內容設定／領取通知） |
| 住戶團購頁 | 以原本布局為底：摘要 → 開團資訊（圖片＋公告同一塊）→ 我的訂單 → 大家的訂單 |
| 住戶團購頁電腦版 | 左右兩欄，右側固定訂購欄 |
| 公告與訂單牆 | 都直接顯示；公告過長才截斷並可展開，訂單牆不收起 |
| 結單時間 | 選填，沒設就不顯示 |
| 住戶團購列表 | 縮圖列表，分「開團中」「已結單」兩段 |
| 列表排序 | 依開團時間，越新越上面 |
| 付款標記 | 點一下切換＋可復原提示，不再每次確認 |
| 結單／重新開放 | 放在左側欄狀態旁，任何分區都按得到，按下先確認 |
| 字體 | 系統字體，不載入 Inter |
| 團主端未發布團購的標籤 | 「待發布」改為「草稿」 |
| 測試 | 畫面測試可依新文字與結構修改，但驗證的行為不可減少 |
| 新增套件 | 允許，但本設計不需要 |

## 設計基礎

### 顏色

以 CSS 自訂屬性定義在 `src/styles/tokens.css`，取代現有 token 與各頁寫死的顏色。

| 角色 | 值 | 用途 |
|---|---|---|
| 操作色 | `#0066cc` | 所有按鈕、連結、選取中項目；唯一的操作色 |
| 聚焦外框 | `#0071e3` | `:focus-visible` 2px 外框、2px 間距 |
| 主要文字 | `#1d1d1f` | 標題、內文 |
| 次要文字 | `#5c5c61` | 說明、時間、欄名（DESIGN.md 的 `#7a7a7a` 對比不足，只用於停用狀態） |
| 頁面底色 | `#f5f5f7` | 頁面背景 |
| 卡片底色 | `#ffffff` | 卡片、表格、輸入框 |
| 表頭底色 | `#fafafc` | 表格標題列 |
| 分隔線 | `#e0e0e0`（強）／`#f0f0f0`（弱） | 卡片框線、表格列分隔 |
| 成功 | 文字 `#1a7f37`／底 `#e3f4e8` | 開團中、已付款、已成團 |
| 提醒 | 文字 `#9a4f00`／底 `#fff1e0` | 草稿、未填戶號、今天／明天結單、未收金額 |
| 危險 | 文字 `#b3261e`／底 `#fdecea` | 錯誤訊息、刪除與取消類操作 |
| 中性狀態 | 文字 `#3a3a3c`／底 `#ececef` | 已結單 |
| LINE 綠 | `#06c755` | 只用於 LINE 登入按鈕 |

所有文字與底色組合在實作時都要以對比檢查驗證 ≥ 4.5:1（大字 ≥ 3:1）；不合格就加深文字色，不改用其他色相。

不使用漸層與卡片陰影。對話框以半透明遮罩區隔；底部固定列用 `#f5f5f7` 約 92% 不透明＋背景模糊。

### 字體與排版

- 字體：`system-ui, -apple-system, "PingFang TC", "Noto Sans TC", "Microsoft JhengHei", sans-serif`，不下載網頁字型。
- 中文不套負字距；內文行高 1.6，標題 1.3。
- 字重只用 400 與 600。
- 字級：住戶端內文 17px；團主端表格與表單 14px；輔助小字最小 12px；頁面標題 20～22px；住戶團購標題手機 17～20px。
- 數字（價格、數量、時間）使用 `font-variant-numeric: tabular-nums`。
- 長中文與 LINE 公告：`white-space: pre-wrap; overflow-wrap: anywhere;`。

### 形狀、按鈕與互動

- 圓角：輸入框與小按鈕 8px；卡片 18px；主要按鈕、分段切換、狀態標籤為膠囊形。
- 按鈕四種：
  - 主要：藍色實心膠囊。
  - 次要：藍框白底膠囊。
  - 工具鈕（表格內、列內）：灰框白底、8px 圓角。
  - 危險：平常為紅字或紅框；只有確認視窗內的確認鈕是紅色實心。
- 按下回饋：`transform: scale(0.95)`；`prefers-reduced-motion` 時關閉。
- **所有可點擊元素觸控範圍 ≥ 44×44px**（交接文件規則）。表格內工具鈕外觀可為 28～32px，以內距或偽元素擴大可點範圍到 44px。
- 所有可點擊元素要有明顯按鈕外觀或連結樣式，並有 `:focus-visible`。
- 只做淺色模式。

## 住戶端

### 團購列表（`/`）

- 頂端細列：左「團購小幫手」，右為 LINE 頭貼（點開可登出）。拿掉綠色大橫幅。
- 標題「團購」，副標「N 團開團中」。
- **開團中**：依開團時間，越新越上面。
- **已結單**：依開團時間，越新越上面；預設顯示最近 5 團，「顯示更早的團購」展開其餘。已結單卡片變淡、縮小。
- 手機：縮圖列表，每列包含 80px 縮圖、標題（最多兩行）、最低價（「$45 起」）、進度條與「62 / 100 個」（金額門檻顯示「$9,600 / $30,000」）、結單時間（有設才顯示）或預計到貨。今天／明天結單以提醒色標示。整列可點，不另放按鈕。
- 電腦：開團中為 4 欄商品卡（白底、18px 圓角、4:3 圖片），已結單為兩欄小列。最大寬度 1200px。
- 沒有圖片時顯示中性佔位，不顯示品牌圖示。
- 狀態資訊（例如已成團、未達門檻、到貨文字）的呈現細節在實作時確認資料來源後再排版。

### 團購頁（`/campaign/<slug>`）

**手機（單欄）：**

1. 頂端細列：「‹ 全部團購」。
2. **摘要**：狀態標籤、標題、價格（一種價格顯示 `$45／個`，多種顯示範圍）、預計到貨、結單時間（有設才顯示）、成團進度（數量或金額）與「還差 N 成團／已成團」、「已有 N 筆訂單・開團 8/14 08:05」。
3. **開團資訊**：圖片在上、公告緊接在下，同一塊。多張圖片時下方有縮圖列；點大圖開啟放大檢視。公告預設顯示約 10 行，超過才出現「展開全文／收合」，短公告整段顯示。
4. **我的訂單**：標題旁顯示自己的期別／戶號與名字。若已送出訂單，上方顯示「你已送出 N 個・$X・最後修改時間」。接著是品項（任選優惠專區與其他商品的分組、折扣說明沿用現有規則）、額外品項（有開放才顯示），以及「結單前都可以回來改數量；要整筆取消請找團主。」
5. **大家的訂單**：直接列出，不收起；自己那筆標「（你）」並淡藍底。超過 20 筆先顯示 20 筆，「顯示全部」展開。
6. **底部固定列**：本次訂單數量與金額（額外品項註明另計）、「明細」（開啟底部面板：各品項小計、折扣、合計、已省金額）、「送出訂單」。沒有變更、沒有品項或結單後停用並說明原因。

**電腦（≥ 1024px，左右兩欄）：**

- 左欄：摘要卡（左標題與時間資訊、右進度）→ 開團資訊卡（左圖右文並排，圖片下有縮圖列）→ 大家的訂單（兩欄排列）。
- 右欄：固定不動的「我的訂單」訂購欄：戶號與名字、「你已送出」、品項（品項多時欄內自己捲動）、合計與「明細」、「送出訂單」、改單規則。

**首次填寫住戶資料：** 沿用現有欄位與規則（期別含「其他」、戶號數字／字母、樓層；LINE 驗證身分只顯示不可改），改為新樣式，出現在「我的訂單」位置。

**已結單：** 數量鈕停用，並顯示「本團已結單，無法修改訂單。」

## 團主端

### 架構與網址

上方導覽：「團購小幫手｜團購｜住戶｜設定」，右側「＋ 建立新團」。

| 網址 | 內容 |
|---|---|
| `/admin` | 首頁：所有團購 |
| `/admin/residents` | 住戶 |
| `/admin/settings` | 設定 |
| `/admin/notification-lab` | 通知測試中心（保留，從設定頁進入） |
| `/admin/campaign/<uuid>` | 依狀態導向預設分區：草稿 → 內容設定；開團中 → 概況；已結單 → 訂單 |
| `/admin/campaign/<uuid>/overview` | 概況 |
| `/admin/campaign/<uuid>/orders` | 訂單 |
| `/admin/campaign/<uuid>/content` | 內容設定 |
| `/admin/campaign/<uuid>/pickup` | 領取通知 |

`vercel.json` 已將 `/admin/(.*)` rewrite 到 `admin.html`，子路徑不需改部署設定。`routing.ts` 維持嚴格的 UUID 驗證，只新增上述固定分區名稱。

### 首頁：所有團購

- 標題「團購」，右側分段切換「全部 N｜開團中 N｜草稿 N｜已結單 N」。
- **待處理提示**：只在需要時出現，點了跳到對應頁。例如：自動結單通知尚未指定接收者（→ 設定）、N 位住戶尚未填戶號（→ 住戶，篩選未填戶號）。
- **表格欄位**：縮圖＋團購名稱（草稿加註「住戶看不到・尚未發布」）、狀態、成團進度（文字＋細進度條）、訂單數、未付款數（結單後才顯示，開團中顯示「—」）、結單時間（未設定顯示「未設定」；今天／明天用提醒色）、時間（開團時間；草稿顯示最後編輯時間）、操作（「複製住戶連結」＋「⋯」：查看住戶頁、刪除團購）。
- **排序**：「全部」依狀態分組（開團中 → 草稿 → 已結單），組內依開團時間越新越上面；草稿依最後編輯時間越新越上面。
- 整列可點，進入該團工作區。
- 「＋ 建立新團」開啟小視窗輸入標題，建立後直接進入該團「內容設定」。
- 刪除團購保留確認視窗與現有圖片清理警告。
- 拿掉原本的「工作概況」四格數字與說明文字。

### 團購工作區：左側欄

由上而下：「‹ 所有團購」、封面圖、團購名稱、狀態標籤＋「結單」或「重新開放」（按下開確認視窗）、結單／到貨／開團時間、分區導覽（概況｜訂單 N｜內容設定｜領取通知）、最底部「住戶連結：複製｜開啟住戶頁 ↗」。

草稿時，概況、訂單、領取通知為停用樣式並說明「發布後可用」；領取通知在開團中顯示「結單後才能使用」。

### 概況

- 標題列：「概況」＋「即時更新」狀態。
- 四個數字：成團進度（含還差多少）、訂單筆數、預估總額、今天新增筆數（結單後改為「未付款 N 筆」）。
- **品項數量**：每個品項一列（代碼、名稱、長條、數量），供叫貨參考。
- **最新訂單**：依最後修改時間新到舊，最多 10 筆；每筆顯示名字、戶號、品項、數量、金額、相對時間；修改過標「已修改」；在團主上次看過之後新增或修改的標藍點（上次查看時間存在團主瀏覽器 localStorage，讀寫失敗時不顯示藍點）。「查看全部 N 筆」前往訂單。
- 已結單時，標題列加「匯出 Excel」，並提示前往領取通知。
- 資料即時更新：訂閱該團 `orders`、`order_item` 的變動後重新載入（見風險）。

### 訂單

- 標題列：「訂單」＋「匯出 Excel」（只在已結單可用；開團中停用並說明原因）。匯出沿用 `orderExport`。
- 總覽：N 筆、總數量、總額、已收金額（N 筆）、未收金額（N 筆）。已收／未收由前端依付款狀態加總。
- 工具列：搜尋（名字或戶號）、篩選「全部｜未付款｜已付款」、排序「戶號（預設，沿用 `compareHousehold`）｜下單時間」。
- **表格欄位**：戶號・姓名、訂購內容、數量、金額（有額外品項加註「＋另計」）、付款、團主備註、「⋯」。
  - 訂購內容用品項標籤「B 2」，滑鼠移上顯示品項名稱，不再重複單價；額外品項以虛線標籤顯示「名稱 ×數量・另計」。
  - **付款**：點一下切換已付款／未付款，立即送出，出現「已將 X 標記為已付款・復原」提示約 5 秒；按復原送出反向更新。失敗時該列顯示錯誤並還原顯示。已付款為綠底，未付款為白底。
  - **團主備註**：點格子進入編輯，Enter 或失去焦點時儲存；Esc 取消；儲存中與失敗在格內顯示。上限 500 字。
  - **⋯ → 取消整筆訂單**：只在開團中可用；保留現有確認視窗與文案（已付款時的退款提醒）。
- 某一列更新中只停用該列，其他列可操作。
- 品項彙總不在此頁重複，統一在概況。

### 內容設定

**上方固定列：** 「內容設定」、儲存狀態（已自動儲存＋時間／儲存中／儲存失敗＋「重試」）、發布狀態（草稿「住戶還看不到」、已開團有未更新變更時「有未更新到住戶頁的變更」）、「預覽住戶頁 ↗」、主要按鈕（草稿「發布並開團」；已開團「更新住戶頁」）。自動儲存時機、失敗不自動重試、發布前需先存檔等既有行為不變。

**跳段標籤：** 公告與圖片｜品項與價格｜成團與時程｜優惠與進階，以 ✓／• 標示是否已填妥。

**四段表單（依順序）：**

1. **公告與圖片**：團購標題（必填）、開團資訊（20,000 字上限與字數）、商品圖片（縮圖格、右上角移除、「加入圖片」可多選，選好即依序上傳，失敗的檔案個別顯示錯誤；最多 10 張；第一張為封面）。
2. **品項與價格**：緊湊表格（代碼、商品名稱（口味）、單價）。最後一列單價按 Enter 新增下一列並聚焦名稱；新列沿用上一列單價；「全部套用同一單價」一次設定；只能刪最後一列（沿用現況）。啟用任選優惠時多一欄「參加任選」。
3. **成團與時程**：門檻類型（數量／總金額）、門檻值、數量單位；預計到貨（貨到通知／指定日期／月份時段）；結單日期開關與日期（台灣時間中午 12:00 自動結單）。沿用現有驗證與說明文字。
4. **優惠與進階**（選填）：全團基本折扣、任選優惠（名稱、最低件數、折數）、允許住戶自填額外品項。每項為開關，開啟才展開欄位。

**右欄：** 住戶頁預覽（新版住戶樣式，可切手機／電腦），下方「發布前檢查」列出缺少的必填項目；缺必填時發布鈕停用並說明原因。

**開團後鎖定：** 品項、單價、折扣、額外品項開關為唯讀，並顯示「已開團，品項與價格已鎖定」；標題、公告、圖片、門檻、時程仍可修改。

### 領取通知

獨立分區，以頁面內步驟取代現有對話框，規則與 gateway 不變：

1. 選擇通知對象：「一期、三期」或「二期」。
2. 確認名單與訊息：可 @ 人數、訊息則數、目前無法 @ 的名單、可編輯的訊息內容。
3. 產生並複製一次性指令，貼到正式社區群組；顯示「此頁尚未代表通知已發送」。

「其他」身分的訂購者不會收到通知的提示保留。只有已結單才能使用。通知測試中心沿用同一元件的 test 模式。

### 住戶（`/admin/residents`）

- 標題「住戶 N 位」、搜尋（名字或戶號）、篩選「全部｜未填戶號｜其他｜已封鎖」。
- 清單列：頭貼、LINE 名稱、期別／戶號（或「其他」、「尚未填戶號」）、加入時間、狀態。
- 操作：「調整戶號」在該列展開編輯（規則沿用：已綁定或「其他」才能調整）；「⋯ → 移除並封鎖」保留確認視窗；已封鎖顯示「解除封鎖」。

### 設定（`/admin/settings`）

- 自動結單通知（沿用 `AutoCloseNotificationSettings` 的三種狀態與文案）。
- 通知測試中心入口。
- 帳號：登出。

## 狀態畫面

- **載入：** 列表、表格、概況用灰色骨架佔位；LINE 登入與 session 驗證的整頁畫面維持。
- **空白：** 首頁無團購 →「建立第一團」；訂單無資料 →「還沒有人下單」＋複製住戶連結；住戶列表無開團中 →「目前沒有開團中的團購」，已結單照常列出。
- **錯誤：** 區塊載入失敗只在該區顯示錯誤與「重試」，保留已載入資料；即時同步中斷顯示頂端細條與「重新同步」（沿用 `syncError`）；分享頁缺少 session 時提供回到 `/` 的操作。
- **處理中：** 按鈕顯示進行式文字並防重複送出；列操作只鎖該列。

## 必須維持的產品規則

以 `docs/AI_AGENT_HANDOFF.md` 第 5 節為準，與畫面直接相關的有：

- 住戶可見狀態只有「開團中／已結單」；`arrived` 顯示為已結單，不提供標記到貨。
- 品項代碼 A…Z、AA…，不加「號」；每項顯示真實名稱與個別價格。
- 住戶訂單牆不得顯示任何人的期別／戶號（含自己）；自己的期別／戶號只出現在「我的訂單」。
- LINE 名稱與頭貼只來自後端驗證資料，不可手填。
- 住戶不能送出空訂單；整筆取消由團主在開團中操作。
- 數量門檻：超過上限的數量不可加入，並說明本次最多可訂多少。
- 額外品項：每單最多 10 筆、每筆 1～20，不計入金額、門檻與折扣。
- 付款只有已付款／未付款，不記錄付款方式。
- Excel 匯出只在結單後、純前端產生。
- 領取通知維持一次性指令＋Reply API，正式與測試嚴格隔離。
- 團主前端不接觸 LINE User ID、Auth UID、community UUID；住戶管理只用 `memberCode`。
- 所有可點擊操作有明顯外觀、`:focus-visible`、≥ 44px 觸控範圍。

## 測試與驗證

- **不動：** domain、services、migration 與 Edge Function 契約測試。
- **會改：** `App`、`AdminApp`、`AdminOrdersPanel`、`CampaignListApp`、`ResidentCampaignListApp`、`ResidentMemberManagementApp`、`PickupNotificationPanel`、`AutoCloseNotificationSettings`、`NotificationTestLab`、`LocalLiveApps`、`RuntimeApp`、`routing`、`components/ui` 的畫面測試，依新文字與結構修改查找方式。
- **行為不可減少：** 自動儲存時機與失敗不自動重試、草稿與發布隔離、開團後鎖定、Realtime 不覆蓋未送出草稿、訂單牆不露戶號、首次綁定只填期別／戶號、結單後停用、session fail-closed 與登出、嚴格的 slug／UUID 路由、LIFF 固定住戶入口相容。修改測試時，原本驗證的行為必須仍被某個測試驗證。
- **新增測試：** 付款切換與復原、備註行內儲存、分區網址與依狀態的預設分區、首頁與住戶列表排序、「你已送出」、圖片多選上傳、品項表 Enter 新增列、發布前檢查、團主端即時更新觸發重新載入。
- **畫面驗收：** 開工前先截改版前基準（375／768／1440，localStorage Demo 各頁），每階段完成後截改版後對照；檢查水平溢出、文字截斷、元素重疊。完成後做無障礙檢查（對比、鍵盤操作、焦點、觸控範圍）。
- **Live 驗證：** 在本機 Supabase（5174）確認團主端即時更新、付款切換、備註、圖片上傳與發布流程；正式站由團主登入驗收。
- 每階段結束跑完整 `npm test`、`npm run lint`、`npm run build`。

## 分階段

每一階段完成都要能單獨上線，未改到的頁面維持可用。

1. **設計基礎與共用元件：** tokens、字體、共用元件改寫與新增；既有頁面套用新 token 後不能破版。
2. **住戶端：** 團購列表、團購頁（手機與電腦）、首次綁定、明細面板。
3. **團主端架構：** 新網址與路由、上方導覽、工作區左側欄、首頁表格、住戶、設定；尚未改寫的分區暫時沿用現有畫面。
4. **團主端概況、訂單、領取通知：** 含團主端即時更新、付款切換與復原、備註行內儲存。
5. **團主端內容設定：** 四段表單、品項表、圖片多選上傳、發布前檢查、新版預覽。

## 風險與待驗證

- **團主端即時更新：** `orders`、`order_item` 已在 `supabase_realtime` publication，住戶端正在使用；需在本機 Supabase 實測團主身分能收到該團變動。若收不到，退回「重新整理」按鈕，並把即時更新列入待辦（可能需要後端調整）。
- **團主 LINE 登入後的子網址：** `liff.login()` 未指定 redirectUri，預期回到目前網址；需實測 `/admin/campaign/<uuid>/orders` 登入後是否回到原分區，若不會則導向該團預設分區。
- **圖片多選上傳：** 逐張呼叫既有上傳 gateway；需確認中途失敗時已上傳的圖片仍正確加入草稿，且自動儲存不會重複觸發。
- **付款復原：** 復原是第二次寫入；若兩次請求在網路上交錯，以最後一次成功的回應為準並重新讀取該列。
- **LINE 內建瀏覽器：** 底部固定列、底部面板、鍵盤彈出與安全區域需在實機確認。
