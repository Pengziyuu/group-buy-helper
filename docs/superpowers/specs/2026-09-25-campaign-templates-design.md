# 團購範本：設計

**日期：** 2026-09-25
**狀態：** 已與團主逐段確認，待寫實作計畫

## 背景與目標

團主常重複開同一家店的團（例如每月一次的冰餅團），每次都要重填公告、圖片、品項、價格與優惠。團主也會定期刪除舊團，所以「從舊團複製」不夠用：舊團刪掉後就沒得複製。

目標：
- 團主可以把任一團購**存成範本**。範本和團購分開保存，舊團刪掉後範本還在。
- 建立新團時可以**從範本建立**，一次帶入所有可重用的內容。

**成功標準：**
- 團主從範本建立的新團，進入內容設定時公告、圖片、品項、價格、門檻與優惠都已填好，只需要設定這次的結單日期與到貨時間就能發布。
- 刪除原本的團購後，範本和範本的圖片完全不受影響。

## 已確認的決策

| 決策 | 結論 |
|---|---|
| 做法 | 獨立範本（不是「從舊團複製」），因為團主會定期刪除舊團 |
| 範本內容 | 存：標題、開團資訊、圖片、品項名稱與單價、成團門檻（類型與數值）、數量單位、全團基本折扣、任選優惠（含參加的品項）、允許住戶自填額外品項、到貨方式為「貨到通知」時照存。不存：結單日期、指定日期或月份時段的到貨、訂單、開團時間、住戶連結 |
| 用範本建立的新團 | 一律是草稿，住戶看不到；發布前品項與價格都能改 |
| 更新範本 | 「存成範本」時可選「存成新範本」或「取代既有範本」 |
| 範本管理位置 | 設定頁新增「團購範本」區（改名、刪除）；挑範本在「＋ 建立新團」視窗 |
| 技術做法 | 範本資料表存一份內容快照（JSON），圖片複製到範本自己的資料夾 |

## 資料與權限

### 新資料表 `campaign_template`

| 欄位 | 型別與規則 |
|---|---|
| `id` | `uuid` 主鍵，預設 `gen_random_uuid()` |
| `name` | `text`，去掉前後空白後 1～100 字；以 `lower(btrim(name))` 建唯一索引，不允許同名 |
| `content` | `jsonb`，見下方「內容格式」 |
| `created_at`、`updated_at` | `timestamptz`；`updated_at` 由既有的更新時間觸發器維護 |
| `updated_by` | `uuid`，預設 `auth.uid()`，參照 `auth.users(id) on delete set null` |

**內容格式**：欄位名稱與前端 `CampaignContent`（`src/services/demoCampaignStore.ts`）一致，但只包含範本要存的欄位：
- 標題與開團資訊：`title`、`announcement`
- 圖片與品項：`images`、`items`（每項 `code`、`name`、`unitPrice`、`active`、`discountEligible`）
- 門檻與單位：`unitPrice`、`threshold`、`thresholdKind`、`amountThreshold`、`quantityUnit`
- 優惠與進階：`baseDiscountRate`、`mixMatchDiscount`、`allowCustomItems`
- 到貨：`arrivalLabel`（只可能是「貨到通知」或省略）

不包含 `autoCloseAt`、`openedAt`。

`items` 只存啟用中的品項：停用的品項是開團後留下的歷史紀錄，不帶到新團。存的時候一律寫 `active: true`，沒有單價的品項用團購的 `unitPrice` 補上（與 `normalizeCampaignContent` 相同）。

**資料檢查**（`check` 約束，沿用既有函式）：
- `content` 是 JSON 物件；
- 標題去空白後 1～200 字；
- 開團資訊不超過 20,000 字；
- `images` 通過 `public.valid_campaign_images`（最多 10 張、`src`／`alt` 格式）；
- `items` 通過 `public.valid_campaign_items`（名稱不可空白等團購草稿同樣的規則），且最多 100 個。

### 權限（RLS）

- 啟用 RLS。
- 只有 `public.is_admin()` 的團主可以 `select`、`insert`、`update`、`delete`。
- `anon` 與一般住戶沒有任何權限。
- 範本不出現在任何住戶端 view、RPC 或排程（自動結單、通知）的查詢中；這些查詢都只讀 `campaign` 相關資料表，不需要修改。

### 圖片

- 範本圖片放在既有 `campaign-images` 儲存空間的 `templates/<範本 id>/<檔名>`。
- 新增函式 `public.template_image_path_is_live(p_name text)`：
  - 路徑第一段是 `templates`；
  - 第二段是 UUID 且對應的範本存在；
  - 呼叫者是團主。
- 新增 `insert`、`update` 兩條 policy，使用上面的函式。既有團購圖片的 policy 不改。
- 刪除：既有 `campaign_images_admin_delete` 已允許團主刪除該空間任何路徑，範本資料夾的清理沿用它。
- 讀取：沿用既有的公開讀取。複製圖片需要讀取來源、寫入目的地，這兩個權限上述規則都已涵蓋。

### 不動的部分

不修改任何現有資料表、view、RPC、policy 或 Edge Function。部署時先上資料庫再上前端；資料庫只新增東西，舊版前端不受影響。

## 流程

### 存成範本

入口：團購工作區左側欄的「存成範本」按鈕，任何狀態（草稿、開團中、已結單）都能用。

1. **內容來源：**以資料庫中已儲存的內容為準，也就是草稿，沒有草稿就用已發布的內容。若內容設定頁還有沒存完的修改，視窗提示「會使用已儲存的內容」。
2. **視窗選項：**
   - 「存成新範本」：名稱預設為團購標題；
   - 「取代既有範本」：從清單選一個。
3. **存成新範本：**
   1. 建立範本列，`images` 先是空陣列；
   2. 把這團的圖片逐張複製到 `templates/<新範本 id>/`；
   3. 更新範本內容，填入新圖片網址。
   - 任何一步失敗：刪除剛建立的範本列與已複製的圖片，顯示「存成範本失敗：{原因}」，不留下半成品。
4. **取代既有範本：**
   1. 把新圖片複製到該範本資料夾，用新檔名，不覆蓋舊檔；
   2. 更新範本內容，名稱不變；
   3. 成功後才刪除舊內容用到、新內容沒用到的圖片。
   - 失敗時舊範本保持原樣，並清掉這次多複製的圖片。
5. **不在我們儲存空間的圖片**（網址不是 `campaign-images` 的公開網址，例如本機示範的網址）：不複製，直接沿用網址。
6. **名稱重複：**顯示「已經有叫「{名稱}」的範本，請改名，或選擇取代既有範本」。

### 從範本建立新團

入口：「＋ 建立新團」視窗，新增「空白團購／從範本建立」切換。

1. 選「從範本建立」並挑一個範本；標題欄自動帶入範本內容的標題，可以修改。
2. 用既有的 `create_campaign_draft` 建立草稿。
3. 把範本圖片逐張複製到新團資料夾 `<新團 id>/`。
4. 用既有的存草稿功能寫入內容，並做以下處理：
   - `autoCloseAt` 設為 `null`；
   - `arrivalLabel` 不是「貨到通知」時改為「貨到通知」；
   - `openedAt` 設為 `null`；
   - 圖片換成新團的網址。

   內容檢查全部沿用團購草稿的規則。
5. 完成後導向新團的「內容設定」。
6. **部分圖片複製失敗：**保留草稿與已複製的圖片，內容設定頁顯示「有 {N} 張範本圖片沒有複製成功，請重新加入」。
7. **建立草稿或寫入內容失敗：**
   - 草稿還沒建立：視窗顯示錯誤，可以重試。
   - 草稿已建立、寫入失敗：仍導向新草稿，並顯示「範本內容沒有完整帶入：{原因}」，讓團主手動補。

### 範本管理（設定頁「團購範本」區）

- 列出每個範本的名稱、品項數、最後更新時間，依最後更新時間新到舊排列。
- **改名：**行內編輯；同名時顯示與「存成範本」相同的錯誤。
- **刪除：**確認視窗「刪除範本「{名稱}」？已用這個範本建立的團購不受影響。」刪除資料列後清掉 `templates/<id>/`；圖片清理失敗只顯示警告，範本仍視為已刪除。
- **沒有範本時：**顯示「還沒有範本。在團購工作區按「存成範本」就會出現在這裡。」

### 刪除團購

不影響範本：範本有自己的圖片副本，刪除團購時既有的清理只刪 `<團購 id>/` 資料夾。

## 畫面

- **團購工作區左側欄：**在「住戶連結」區塊之上加「存成範本」按鈕（次要按鈕樣式）。
- **「存成範本」視窗：**
  - 兩個選項用 `SegmentedControl`：「存成新範本」「取代既有範本」；
  - 新範本：名稱輸入欄；
  - 取代：範本下拉選單，沒有範本時不能選；
  - 按鈕「儲存範本」，處理中顯示「儲存中…」；
  - 成功後關閉，左側欄顯示「已存成範本「{名稱}」」。
- **設定頁「團購範本」區：**沿用團主端表格樣式；640px 以下轉成小卡。
- **「＋ 建立新團」視窗：**沿用現有視窗，多「空白團購／從範本建立」切換與範本選單。
- **本機示範（localStorage Demo）：**
  - 範本存在瀏覽器的 localStorage，圖片直接沿用網址；
  - 建立、取代、改名、刪除、從範本建立都能在示範模式走完；
  - 讀寫失敗時顯示錯誤，不影響其他功能。
- 文案全部繁體中文；可點範圍、對比、聚焦外框沿用改版規則：
  - 團主端 1024px 以上 ≥ 24px，以下 ≥ 44px；
  - 文字對比 ≥ 4.5:1；
  - 聚焦外框 `2px solid #0071e3`。

## 程式結構

- **資料庫：**一支新 migration，內容包括：
  - 資料表、索引、檢查、RLS；
  - `template_image_path_is_live`；
  - 兩條 storage policy；
  - 權限授予。
- **前端服務：**新 gateway `src/services/campaignTemplateGateway.ts`，提供 `list`、`create`、`replace`、`rename`、`delete`、`createCampaignFromTemplate`。圖片複製用 Supabase Storage 的 `copy`。
- **純函式：**`src/domain/campaignTemplate.ts`，可單獨測試，包括：
  - 從團購內容取出範本內容（排除不存的欄位）；
  - 從範本內容產生新團內容（清結單日期、改回貨到通知）；
  - 由公開網址判斷圖片路徑、產生新路徑。
- **畫面元件：**放在 `src/components/organizer/`：
  - `SaveTemplateDialog`
  - `TemplateSettings`（設定頁區塊）
  - 修改 `CreateCampaignDialog`
- **組裝：**`LocalLiveAdminApp` 與 `RuntimeApp` 的示範模式各自提供範本 gateway。示範模式的 gateway 用 localStorage 實作同一個介面。

## 測試與驗證

- **資料庫驗證腳本** `scripts/verify_campaign_templates.py`，照既有 `verify_*.py` 的做法，使用臨時 Auth 使用者，驗證：
  - 團主能建立、讀取、改名、刪除範本；
  - 住戶與未登入者讀不到也寫不進；
  - 同名範本被擋；
  - 壞內容被擋：空白品項名稱、超過 10 張圖、公告超過 20,000 字；
  - 範本不存在時不能上傳到 `templates/<id>/`；
  - 刪除範本後圖片可以清掉。
- **前端單元與畫面測試：**
  - 內容取出與轉換的純函式：不存的欄位確實被排除，結單與到貨被重設；
  - 存成新範本、取代、名稱重複、半路失敗時的清理與提示；
  - 從範本建立：成功導向內容設定、部分圖片失敗的提示、寫入失敗的提示；
  - 設定頁的改名、刪除、空狀態；
  - 示範模式可以走完整流程。
- **既有行為不可減少：**建立空白團購、刪除團購與圖片清理、草稿與發布隔離、開團後鎖定。
- **截圖：**`scripts/capture-pages.mjs` 既有頁面比對（設定頁會多「團購範本」區），並檢查 375／768／1440 無水平溢出。

## 部署

1. 在本機 Supabase 套用 migration 並跑 `verify_campaign_templates.py`。
2. 把 migration 推到正式 Supabase，並在正式環境跑驗證腳本。
3. push 前端（Vercel 自動部署）。

資料庫只有新增，第 2 步之後、第 3 步之前舊版前端照常運作。

## 風險與待驗證

- **Storage `copy` 權限：**需在本機 Supabase 實測團主能把 `<團購 id>/…` 複製到 `templates/<id>/…`，以及反向複製。若 `copy` 因權限規則失敗，改用「下載後重新上傳」，行為不變，只是比較慢。
- **大量圖片：**一次最多 10 張，逐張複製；進度顯示沿用「處理中」按鈕文字即可，不另做進度條。
- **既有內容欄位日後增加：**範本內容格式沿用 `CampaignContent` 的欄位名稱。日後團購新增可重用的設定時，要同時加進「從團購內容取出範本內容」的純函式。這一點寫進 `docs/AI_AGENT_HANDOFF.md`。

## 範圍外

- 直接在範本上編輯內容：要修改就從範本建立團購、修改後再「取代既有範本」。
- 範本預覽頁。
- 範本分享給其他團主或其他社區。
